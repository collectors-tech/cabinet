## Summary
Add representative sample content across the available Cabinet categories so live UI changes are easier to verify visually and behaviorally during development/review.

## Problem
Right now it is hard to tell whether UI/category-related changes are actually working because several categories/views do not have enough distinct seeded/sample content to make changes obvious in the running app.

## Requested outcome
- populate all relevant inventory/content categories with representative sample content
- ensure categories are visually distinct enough that filtering/selection/state changes are easy to verify in live review
- use seeded/demo-safe data suitable for local/demo lanes

## Why this matters
- improves review clarity in demo instances
- makes category/property changes easier to validate
- reduces false uncertainty during UI implementation and exploratory review

## Suggested acceptance targets
1. Each available category has visible sample entries in the demo dataset
2. Category changes are obvious in the inventory UI during live review
3. Demo/sample data remains safe for local/demo lanes and does not depend on manual one-off setup
